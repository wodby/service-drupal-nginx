# Nginx for Drupal 11 on Wodby

What this service adds to the PHP Nginx service it is based on. Check it before adding rewrite rules or web server configuration for Drupal to the repository.

## Preset

The service sets `NGINX_VHOST_PRESET` to `drupal11`, the image's rule set for Drupal 11. Its template is declared as a config file of this service and can be overridden there. What it does:

- Paths that match no file go to Drupal's `index.php`. Clean URLs need no configuration.
- Only Drupal's entry points run as PHP: `index.php`, `update.php`, `core/install.php`, `core/rebuild.php` and `core/authorize.php`. Any other `.php` path returns 404, so a custom PHP script in the document root is not reachable.
- Image styles and aggregated CSS and JS under a `files` directory are served when they exist and generated by Drupal when they do not.
- `sites/<site>/files/private/` is never served directly; `/system/files/` goes to Drupal, which controls access.
- Files with the extensions Drupal's own `.htaccess` protects (such as `.yml`, `.twig`, `.module`, `.sql`), `composer.json`, `composer.lock`, and the paths `/patches` and `/backup` return 404.
- `rss.xml` and `sitemap.xml` are passed to Drupal when no such file exists. Other missing `.xml` paths return 404 unless `NGINX_DRUPAL_ALLOW_XML_ENDPOINTS` is set.
- The default `Content-Security-Policy` allows framing by the same origin, and Nginx leaves `X-Frame-Options` and `X-Content-Type-Options` to Drupal.

## Settings shared with the PHP service

The `docroot` and `sitedir` settings (variables `DOCROOT_SUBDIR` and `DRUPAL_SITE`) are taken from the linked PHP service. Change them there; both services then resolve the Drupal root and the site directory to the same paths.

## Files

- The files volume of the linked PHP service is mounted here read-only at `/mnt/files`.
- On start, the service's init action (`WODBY2_SERVICE_INIT_ACTION`, here `init`) makes `sites/<site>/files` under the Drupal root a link to `/mnt/files/public`, so uploaded public files are served by Nginx directly from the volume.
- The link cannot be made when `sites/<site>/files` in the image holds anything other than a `.gitignore`: keep uploaded files out of the repository.

## Build

Only the document root subdirectory of the PHP service's source is copied into this image, at the same path as in the PHP image. Files outside the document root, such as `vendor` or `config`, are not in the web server image.

## Variables specific to Drupal

`NGINX_DRUPAL_FILE_PROXY_URL` (redirects requests for missing files under `sites/*/files` to another site, for an environment without a copy of the files), `NGINX_DRUPAL_HIDE_HEADERS`, `NGINX_DRUPAL_ALLOW_XML_ENDPOINTS`, `NGINX_DRUPAL_REMOVE_INDEXPHP`, `NGINX_DRUPAL_NOT_FOUND_REGEX`.

## Check the result

- `nginx -T` shows the preset in effect.
- `ls -l <Drupal root>/sites/<site>/files` inside this service shows the link to the files volume.
